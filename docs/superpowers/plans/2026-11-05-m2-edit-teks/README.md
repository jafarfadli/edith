# Edith M2 — Edit Teks: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each task lives in its own file in this folder; read README.md (this file) + your task file only.

**Goal:** Edit the PDF's own text: click a paragraph, rewrite it with per-range rich text (font, size, color, background, B/I/U/S, alignment), keep the PDF's embedded font when it can draw the new text, use the same rich text in text boxes, and Find & Replace across original paragraphs and text boxes — all baked into the downloaded PDF exactly where the editor showed it.

**Architecture:** The API gains a font table + paragraph extraction (`GET /documents/{id}/text`), serves reusable embedded fonts (`GET /documents/{id}/fonts/{ref}`), and bakes the new `text.edit` op: a text-only redaction pass removes the paragraph's original glyphs (images and vector art untouched, a separate pass from `redact.add`), then the client's layout is drawn with TextWriter using the bundled or the original font, plus background/underline/strike bands. The web client stays the layout authority: it turns an extracted paragraph into a `TextBox` that reproduces the original line breaks, edits it in a Tiptap rich-text editor (one `run` mark carrying the whole run style), covers the original lines with white masks on screen (matching the bake's redaction), and searches/replaces over original paragraphs and text ops with one undo step for Replace All.

**Tech Stack:** As M1 (Python 3.12/uv/FastAPI/PyMuPDF 2.1 · Next.js 16/React 19/Konva/zustand/fontkit/pdfjs-dist 6/Vitest/Playwright) plus **Tiptap 3** (`@tiptap/core`, `@tiptap/pm`, `@tiptap/react`, `@tiptap/extension-document`, `@tiptap/extension-paragraph`, `@tiptap/extension-text`, `@tiptap/extensions`, all `^3.32.2`).

Spec: `docs/superpowers/specs/2026-11-05-pdf-editor-design.md` — sections Font, Teks (Model/Ekstraksi/Layout), Interaksi edit teks asli, Find & Replace, Skema Ops (`text.edit`, `FontRef`, `Run`), Urutan bake step 3, Testing, Kriteria Selesai. - **Spike results (PyMuPDF 2.1 / MuPDF 1.28.6, fontkit 2, Tiptap 3.32.2) — the design relies on these:**
  - `page.get_text("dict")` coordinates are unrotated-CropBox points even when `/Rotate` is set; rotated text has `line["dir"] != (1, 0)` (e.g. `(0, -1)`).
  - **Span font names come from the font program, not BaseFont**: BaseFont `Arimo Regular` → span `Arimo-Regular`; an embedded CFF Courier → span `NimbusMonoPS-Regular`. Map spans to fonts by `name_key()` = lowercase alphanumerics of the name without the `ABCDEF+` prefix, matching either the BaseFont or `pymupdf.Font(fontbuffer=…).name` of the embedded program. A name shared by two of the page's fonts is ambiguous → no original font for that span.
  - `doc.extract_font(xref)` → `(name, ext, type, bytes)`; `ext` is `n/a` (not embedded), `ttf`, `otf`, `cff`/`cid` (bare CFF), `pfa`/`pfb`. Bare CFF does not parse in fontkit ("Unknown font format"). **TTF subsets made by PyMuPDF (`doc.subset_fonts()`) have no cmap**: `has_glyph()` is 0 for every character and fontkit throws → not reusable. A fontTools subset keeps its cmap → reusable (`has_glyph` true only for its glyphs).
  - Reusable = embedded `ttf`/`otf`, loads with `pymupdf.Font(fontbuffer=…)`, and maps at least one of `a–z A–Z 0–9`. Text drawn with such a font via TextWriter keeps the floor-1/1000-em width quantization (checked: Arimo/Tinos/Tinos-subset advances equal `floor(glyph_advance·1000)/1000·size`), and fontkit parses the same bytes with identical advance widths.
  - **TextWriter silently substitutes a builtin font (e.g. Noto Serif) for glyphs the font lacks** → the bake must reject an original-font run with a missing glyph (`bake_failed`), and the client must switch such runs to the substitute before sending (original → substitute → Arimo; Arimo/Tinos/Cousine/Carlito cover Latin, Greek and Cyrillic; Lato/Poppins/Caladea do not).
  - **Redaction for `text.edit`:** MuPDF removes every glyph whose (font-bbox-tall) box touches a redaction rect. The spec's "line bbox shrunk by 0.5 pt" deletes the next line at a leading ≤ 1.0 × size (tested 12 pt text at 12 pt leading). A 1 pt band centred `0.3 × size` above each original baseline, inset 0.5 pt horizontally, removes every glyph of that line (incl. `.`/`,`) and nothing on the neighbouring lines down to a leading of 0.8 × size, nor a same-baseline neighbour in another column. `add_redact_annot(rect, fill=False)` paints nothing. `apply_redactions(images=PDF_REDACT_IMAGE_NONE, graphics=PDF_REDACT_LINE_ART_NONE, text=PDF_REDACT_TEXT_REMOVE)` keeps images and line art; a second `apply_redactions` with `PDF_REDACT_IMAGE_PIXELS` + `PDF_REDACT_LINE_ART_REMOVE_IF_TOUCHED` for `redact.add` still blackens pixels.
  - MuPDF splits the last line of a centered/right-aligned paragraph, and wide justified word gaps, into blocks/lines of their own → extraction re-joins same-baseline pieces closer than 2 em and continues a block with the next one when it sits right below, overlaps horizontally and has the same size.
  - With the substitute's quantized metrics, greedy re-wrapping at width `max(bbox width, widest measured original line) + 0.01` reproduces wrapped lines exactly (left/justify/center/right, Helvetica→Arimo, Times→Tinos, Courier→Cousine). Hand-broken lines (addresses, short lines) are not wraps: where the next line's first word would have fit, the break is "hard" and becomes a logical paragraph — then every original line survives reflow.
  - `pymupdf.Font(...).glyph_advance()` is a float: quantize with `math.floor(round(adv * 1000, 3))` (a plain floor of e.g. 555.9999 would lose a unit).
  - Spaces drawn with Tinos (bundled or reused) read back as U+00A0 in `get_text()` (Arimo does not); pdf.js shows them as spaces. Extraction maps U+00A0 and tabs to spaces.
  - Tiptap 3: `setMark` merges attributes per text node; typed text inherits the marks at the caret; `splitBlock` keeps them. With `immediatelyRender: false` (and React StrictMode) `useEditor` may create the editor twice: track the live instance with an effect on the returned `editor`, not in `onCreate`; keep the session content in a module variable updated `onUpdate` (it must still be readable after unmount). Playwright `fill()` on the ProseMirror element works.
  - Google Fonts CSS API (old UA) serves full static TTFs: Noto Sans 2.2 MB, Noto Serif 1.8 MB, Merriweather 2.3 MB, Carlito 2.4 MB, all others 0.06–1.3 MB per family.
- **Decoration geometry (shared contract, `apps/web/src/lib/textDecor.ts` ↔ `apps/api/edith/bake/text.py`):** per segment of advance `w` drawn at `(x, baseline)` with run size `s`: background `[x, baseline − 0.9 s, w, 1.15 s]` under the glyphs; underline `[x, baseline + 0.075 s, w, 0.06 s]` and strike `[x, baseline − 0.3 s, w, 0.06 s]` over the glyphs, filled in the run color. Order: all backgrounds, all glyphs, all lines. `w` is the quantized advance of the segment text.
- **Screen mask of an edited paragraph:** per original line `[x0 − 0.5, baseline − 0.95 s, w + 1, 1.2 s]`, white, under every object (M2 shows it, the bake redacts).
- **`text.edit` identity:** `(pageKey, paragraphId)`; `paragraphId` = `g{n}` of the page's *source* page (`src.index`), stable for a given file because the API re-runs the same extraction at bake. At most one op per pair (schema validator). A duplicated page (M4) gets copies of its `text.edit` ops with the new `pageKey`; the bake already resolves them through the layout's `src.index`.
- **Fonts in M2:** 21 families — Arimo, Tinos, Cousine, Carlito, Caladea (metric-compatible substitutes) + Inter, Roboto, Open Sans, Lato, Montserrat, Poppins, Source Sans 3, Lora, Playfair Display, Source Serif 4, PT Serif, JetBrains Mono + Dancing Script, Caveat, Great Vibes, Sacramento. Files `${family without spaces}-${Regular|Bold|Italic|BoldItalic}.ttf`; script families ship only the styles Google serves (Dancing Script/Caveat: Regular, Bold; Great Vibes/Sacramento: Regular). Missing styles fall back bolditalic → bold → italic → regular, identically in `FontRegistry.path` and the web `pickFile`. `packages/fonts/files` grows from 4.5 MB to ~16 MB.
- **Substitute rule (`FontRegistry.substitute(name, flags)`):** `parse_font_name` keys the name (drop subset prefix, take the part before the first `-`/`,`, lowercase alphanumerics), then strip `regular|bolditalic|boldoblique|bold|italic|oblique|roman|book|mt|ps` suffixes one at a time until an alias matches; no match → span flags (mono 8 → Cousine, serif 4 → Tinos, else Arimo). Bold = name contains bold/black/heavy/semibold/demibold/demi or flag 16; italic = italic/oblique or flag 2.

## Decisions (and why)

- **Rich text editor: Tiptap**, as the spec says, with a schema of only `doc`/`paragraph`/`text` and **one custom `run` mark holding the whole run style** (`font` FontRef, `size`, `color`, `bgColor`, `underline`, `strike`). Bold/italic are font changes (each style is its own `FontFace`), so the stock bold/italic marks (CSS faux bold) would not match the bake. A contenteditable is only the typing surface; outside a session Konva draws the laid-out runs glyph by glyph (M1 `TextNode`), so the SVG `TextLayer` of the spec is not needed (see deviations).
- **Original paragraphs on screen:** pdf.js still renders the page. Unedited paragraphs get transparent Konva hit rectangles under the page's objects (hover outline, click = select with left/right width handles, drag/resize/double-click → `text.edit`); edited paragraphs get white masks over their original lines and are drawn by Konva from the op — the same thing the bake does with redaction + TextWriter.
- **One logical paragraph per hard break:** the box built from an extracted paragraph splits it where the original break was not a wrap, so unchanged text keeps its lines (Kriteria Selesai) while edited text reflows.
- **Font choice on the client, explicit in the op** (spec): a run keeps `{kind:"original", ref}` only when that font is reusable, loaded, and has every glyph of the run; else the document's substitute; a bundled family missing a glyph → Arimo. Toggling bold/italic on an original run uses a reusable variant of the same family in the document if there is one, else the substitute.
- **Find & Replace** runs in the client over search targets in page/reading order: unedited original paragraphs (`para:<pageKey>:<id>`, their joined run text) and text ops (`op:<id>`, paragraphs joined by `\n`). Replace keeps the style of the first matched character; on an original paragraph it creates the `text.edit` (offsets mapped through the hard-break split); Replace All is one `putObjects` call = one undo step.
- **History coalescing** (M1 backlog): `updateObject(id, patch, {coalesce: key})` merges updates with the same key within 1 s into one undo step — used by the properties sliders/inputs, text style changes and arrow-key nudges. A rich-text session stays one step (M1 behaviour).

M1 backlog items folded in where M2 touches the code: history coalescing (Task 10/12: slider drags, size typing, nudges), `fetch.mjs` error handling and the all-styles font test (Task 1), `sync-fonts` purging stale files (Task 1), the stray blank line in `bake()` (Task 6).

## Deviations from spec (intentional, M2)

- **Redaction rect for `text.edit`**: a 1 pt band at `baseline − 0.3·size` per original line instead of the line bbox shrunk by 0.5 pt — the spike showed the bbox rect deletes the neighbouring line at tight leading.
- **Paragraphs and fonts come from a new `GET /documents/{id}/text`** (all pages, fetched once in the background) instead of being part of `structure` (keeps the editor opening fast; ~7 ms/page extraction).
- **`Segment.width` is not added to the op**; the bake computes the quantized width it needs for decorations itself (same rule as the client).
- **No SVG `TextLayer`**: text is drawn by Konva (M1) and original paragraphs are hit-tested in the Konva overlay.
- **Font registry**: 21 of the spec's families; Noto Sans/Serif and Merriweather (6.3 MB together) are left out — Arimo/Tinos/Cousine already cover Latin/Greek/Cyrillic, which is what the "Unicode fallback" was for. Script fonts are included now (M3 signatures need them; 1 MB).
- **Paragraph splitting rules** are the spec's three plus: a line on the same baseline closer than 2 em joins the previous line; a block continues the previous one when directly below/overlapping/same size; the indent rule is disabled inside right-aligned blocks and needs the right edge not to move in (so centered text is not split).
- **Layout parity is checked geometrically, not with screenshots**: unit tests assert every fixture paragraph is re-laid out on its original lines with baselines within 0.5 pt (Helvetica/Times/Courier substitutes, all alignments, hand-broken lines), API tests assert baked baselines, and the E2E asserts that the downloaded PDF's baselines equal the editor's layout (±0.5 pt) and that every original line still starts at the same place with the same word. Pixel comparison between pdf.js and the PyMuPDF raster was left out (anti-aliasing noise; M1 measured glyph origins within 3e-5 pt).
- **Deleting a selected `text.edit` op reverts the paragraph** to the original (button label "Kembalikan teks asli"); emptying the paragraph's text in the editor keeps an op with no text (= deletes the original paragraph).
